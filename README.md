# Практическая работа №7
## Межпроцессное взаимодействие (IPC)

**Вариант:** B  
**Среда выполнения:** Linux / WSL  
**Язык программирования:** Python 3

## 1. Цель работы

Изучить механизмы межпроцессного взаимодействия (IPC), реализовать обмен данными между процессами с использованием именованных каналов FIFO, Unix domain sockets, разделяемой памяти и Pipe. Сравнить особенности и производительность этих механизмов.

## 2. Выполненные задания

### Задание 1. Клиент–сервер на именованных каналах FIFO

Реализован сервер, который получает арифметические выражения от клиентов через именованный канал FIFO и отправляет результаты через отдельные FIFO для ответов.

**Файлы:**
- `fifo_server.py` — сервер.
- `fifo_client.py` — клиент.
- `ipc_common.py` — вычисление арифметических выражений.

**Запуск сервера в первом терминале:**

```bash
python3 fifo_server.py
```

**Отправка запроса во втором терминале:**

```bash
python3 fifo_client.py "2 + 3 * 4"
```

Ожидаемый результат:

```text
14
```

Пример другого запроса:

```bash
python3 fifo_client.py "10 / 2"
```

Результат:

```text
5.0
```

Сервер обрабатывает запросы последовательно. Для каждого клиента создаётся отдельный канал ответа.

### Задание 2. Клиент–сервер на Unix domain sockets

Реализован сервер с использованием `socket.AF_UNIX` и `socket.SOCK_STREAM`. Для обработки каждого подключённого клиента сервер запускает отдельный процесс.

**Запуск сервера:**

```bash
python3 unix_server.py
```

**Запуск клиента:**

```bash
python3 unix_client.py "2 + 3 * 4"
```

Ожидаемый результат:

```text
14
```

Для проверки одновременной работы нескольких клиентов можно выполнить:

```bash
python3 unix_client.py "1 + 1" &
python3 unix_client.py "2 + 2" &
python3 unix_client.py "3 + 3" &
wait
```

Unix domain sockets обеспечивают обмен данными между процессами на одном компьютере без использования сетевого IP-соединения.

### Задание 3. Передача массива через разделяемую память и Pipe

В файле `shared_memory_demo.py` реализована передача массива из 10⁷ чисел типа `float64` с использованием `multiprocessing.shared_memory`.

Размер массива составляет приблизительно 80 МБ.

Один процесс записывает данные в разделяемую память, а другой получает доступ к той же области памяти. Для уведомления о завершении записи используется `Pipe`.

**Запуск:**

```bash
python3 shared_memory_demo.py
```

Программа проверяет несколько элементов массива, измеряет время работы и сравнивает его с передачей массива через `Pipe`.

Фактическое время выполнения зависит от характеристик компьютера и загруженности системы.

### Задание 4. Сравнение механизмов IPC

Для дополнительного сравнения реализован файл `benchmark.py`.

**Запуск:**

```bash
python3 benchmark.py
```

Для изменения размера буфера:

```bash
python3 benchmark.py --mb 32
```

Результаты измерений выводятся в терминал.

| Механизм | Синхронизация | Объём данных | Особенности |
|---|---|---|---|
| FIFO | Требуется согласование чтения и записи | Поток байтов | Простая организация обмена |
| Unix domain sockets | Требуется протокол обмена | Поток байтов | Поддержка нескольких клиентов |
| Shared memory | Требуется синхронизация доступа | Большие массивы данных | Быстрый доступ к общей области памяти |
| Pipe | Требуется согласование обмена | Объекты и байты | Удобная передача данных между процессами |

## 4. Ответы на контрольные вопросы

### Вопрос 1. Почему разделяемая память — самый быстрый и самый опасный механизм IPC?

Разделяемая память позволяет нескольким процессам обращаться к одной области памяти. При работе с большими объёмами данных не требуется постоянно пересылать их между процессами, поэтому этот механизм может быть быстрее других способов IPC.

Однако разделяемая память опасна тем, что процессы могут одновременно изменять одни и те же данные. Это может привести к гонкам данных, повреждению информации и непредсказуемым результатам. Для правильной работы необходимо использовать синхронизацию, например блокировки или семафоры.

### Вопрос 2. Что произойдёт при записи в pipe, у которого закрыты все читающие концы?

В Linux при записи в канал, у которого нет открытых читающих концов, процесс получает сигнал `SIGPIPE`. По умолчанию этот сигнал завершает процесс. Если сигнал игнорируется или обрабатывается, операция записи завершается ошибкой `EPIPE`. В Python обычно возникает исключение `BrokenPipeError`.

## 5. Вывод

В ходе практической работы были изучены и реализованы основные механизмы межпроцессного взаимодействия: FIFO, Unix domain sockets, shared memory и Pipe.

Было установлено, что FIFO удобны для простого обмена данными, Unix domain sockets подходят для организации клиент–серверного взаимодействия, а разделяемая память эффективна при работе с большими объёмами данных. При этом использование разделяемой памяти требует особого внимания к синхронизации.

Таким образом, выбор механизма IPC зависит от объёма передаваемых данных, требований к производительности, сложности взаимодействия и необходимости синхронизации процессов.
